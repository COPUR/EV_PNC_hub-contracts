# EV_PNC_hub-contracts

Hub specs and contracts for Hubject, GIREVE and e-clearing.net, kept as data: requirements, hub profiles, conversion tables, Gherkin conformance features, pinned vendor files and drift checks. No runtime code; the adapters that load these files live in [EV_PNC_hub-gateway](https://github.com/COPUR/EV_PNC_hub-gateway).

Part of the **EV_PNC** platform, a neutral eMSP integration layer. Hubs are future integration points for the Europe expansion: nothing here needs a contract, an account or any contact with a hub. Everything is derived from published specifications and public implementation guides; no live hub system is probed.

## Layout

| Path | Content |
|---|---|
| `_sources/` | Pinned public vendor files (OICP 2.3 EMP and CPO OpenAPI, OPCP MO subsets). Generated by `tools/fetch_public_contracts.py` from upstream commits in `_sources/pins.json`; never hand-edited. CC BY-SA 4.0, Hubject GmbH (see `_sources/ATTRIBUTION.md`). |
| `profiles/` | Hub rules as data: how each hub deviates from the standard it speaks, the OCPI 2.3.0 to 2.2.1 conversion table, the Hubject authorize decision to StatusCode mapping, PNCP and OPCP event AsyncAPI. Each entry carries `source` and `confidence` (`fact`, `inference`, `unknown`). See `profiles/README.md`. |
| `specs/` | 122 requirements (`RH-<HUB>-<AREA>-<NNN>`) per hub with plan, tasks and Gherkin acceptance features, the hub ADRs 0001 to 0006, and `traceability.csv` (requirement, source, contract, acceptance, task). |
| `tools/`, `tests/` | The pin fetcher with its drift check, and the unit tests that guard the bundle. |

## Checks

```bash
uv run --with pyyaml python -m unittest discover -s tests   # profiles parse, traceability has no broken reference
uv run tools/fetch_public_contracts.py --check             # _sources/ equals a fresh build from the pins
```

CI (`contracts-drift.yml`) runs both on every pull request and a weekly upstream check that reports newer Hubject commits without moving the pins.

## Rules

- A requirement enters `specs/` only as a cited fact or a stated project requirement. Everything uncertain stays `unknown` or `inference` in a profile until a source moves it.
- Changing a profile changes adapter behaviour: the hub-gateway vendors `profiles/` and its CI fails when its copy differs from the pinned commit of this repository.
- Gherkin tags: `@mock` runs in CI against hub mocks, `@sandbox` needs hub test access (not available), `@pending-confirmation` marks scenarios whose expected value is an inference.

## Status

Hubject and GIREVE profiles, conversion table and specs are complete for the pilot scope. e-clearing.net is a phase 5 reference (ADR-0004). Not production ready.
